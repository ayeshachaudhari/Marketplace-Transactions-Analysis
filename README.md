#  Marketplace Transactions – Commercial Performance Case Study (MySQL)

A SQL case study on an online marketplace's order-level data. It reconstructs the monthly commercial performance bridge, checks customer concentration risk, measures discount dependency, evaluates customer-acquisition cohort quality, and models the impact of reducing discounts.

##  Data Used

The script works on one flat, order-line level table: `marketplace_transactions`.

| Column | Meaning |
|---|---|
| `order_id` | Unique order identifier |
| `customer_id` | Customer who placed the order |
| `order_timestamp` | Order date (parsed with `STR_TO_DATE`) |
| `order_status` | Delivered / Cancelled / Returned |
| `product_category` | Product category |
| `quantity` | Units ordered |
| `unit_selling_price` | Selling price per unit |
| `discount_amount` | Discount given on the order line |
| `refund_amount` | Amount refunded to the customer |
| `seller_commission_rate` | Commission rate charged to the seller |
| `payment_fee` | Payment gateway cost |
| `fulfilment_cost` | Shipping / warehousing cost |
| `acquisition_channel` | Channel through which the customer was acquired |
| `customer_acquisition_date` | Customer's acquisition date (used for cohorts) |
| `customer_segment` | Customer segment |

> The script does not create or load this table. Import your dataset (for example a CSV) into `case_study_1.marketplace_transactions` before running the analysis. Column names must match the ones above.

##  Key Metric Definitions

| Metric | Formula |
|---|---|
| **GMV** | `quantity × unit_selling_price − discount_amount` |
| **Delivered GMV** | GMV where `order_status = 'Delivered'` |
| **Cancelled GMV** | GMV where `order_status = 'Cancelled'` |
| **Returned GMV** | GMV where `order_status = 'Returned'` |
| **Seller commission** | Delivered GMV × `seller_commission_rate` |
| **Contribution proxy** | Delivered GMV − `refund_amount` − `payment_fee` − `fulfilment_cost` |
| **Discount rate** | Total discounts ÷ gross sales value |
| **Contribution per delivered order** | Contribution proxy ÷ delivered orders |

##  Business Questions Solved

### Q1 — Commercial Performance Bridge
Monthly GMV, delivered / cancelled / returned GMV, discounts, refunds, seller commission, payment fees, fulfilment costs and contribution proxy. Month-over-month growth for order count, GMV, delivered GMV and contribution proxy, to find months where **GMV grows but contribution shrinks**.
*Techniques: CTEs, conditional aggregation, `LAG()`, `NULLIF`.*

### Q2 — Customer Concentration & High-Value Customers
Share of delivered GMV and contribution generated by the **top 1%, 5% and 10%** of customers, repeat-purchase participation, and customers above the **90th percentile of GMV with negative contribution**. Answers: *are the biggest customers also the most profitable?*
*Techniques: `NTILE(100)`, `PERCENT_RANK()`, cumulative shares, multi-step CTEs.*

### Q3 — Discount Dependency & Commercial Quality
Discount rates by product category and acquisition channel, categories where higher discounts coincide with lower contribution per order, customer-segment comparison (average order value, repeat frequency, discount dependency, refund burden, contribution) and high-value transactions with weak post-discount economics.
*Techniques: grouped ratios, segment comparison, category ranking, filtering with `HAVING`.*

### Q4 — Acquisition Cohort Quality
Acquisition-month cohorts comparing **first-purchase contribution**, **90-day cumulative contribution** and **repeat-purchase rate** by channel. Flags cohorts whose first purchase looks profitable but whose 90-day economics deteriorate, and marks **incomplete 90-day windows**.
*Techniques: cohort building, date arithmetic, window functions, conditional flags.*

### Q5 — Discount Reduction Scenario & Break-Even
Current monthly contribution by category, a **10% discount-expense reduction** scenario, the **break-even delivered-GMV decline** that cancels the benefit, and the categories with the **smallest tolerance for volume decline**.
*Techniques: scenario modelling, break-even calculation, category-level ratios.*

##  SQL Concepts Used

- Conditional aggregation (`SUM(CASE WHEN ...)`)
- CTEs (multi-step `WITH` queries)
- Window functions: `LAG()`, `NTILE()`, `PERCENT_RANK()`
- Date functions: `STR_TO_DATE`, `DATE_FORMAT`, `DATEDIFF`
- Percentile-based segmentation and concentration analysis
- Cohort analysis and retention-style metrics
- Safe division with `NULLIF`
- Scenario / break-even modelling

2. Clone the repository:

   ```bash
   git clone https://github.com/<your-username>/<your-repo-name>.git
   cd <your-repo-name>
   ```

3. Create the database and import your data:

   ```sql
   CREATE DATABASE case_study_1;
   USE case_study_1;
   -- Import your dataset into the table `marketplace_transactions`
   -- (e.g. using MySQL Workbench → Table Data Import Wizard)
   ```

4. Open `marketplace_transactions_case_study.sql` in MySQL Workbench and run it question by question.

>  Each question is split into small numbered steps. Run one step at a time to see its intermediate result.

##  Notes & Assumptions

- Contribution proxy is calculated on **Delivered** orders only, after refunds, payment fees and fulfilment costs. It is a proxy, not audited profit.
- Seller commission is reported in the monthly bridge, but is not deducted in the contribution proxy.
- `order_timestamp` is parsed with `STR_TO_DATE(order_timestamp, '%Y-%m-%d')`, so dates are expected in `YYYY-MM-DD` format.
- 90-day cohort windows that have not fully elapsed in the data are flagged as **incomplete**.
